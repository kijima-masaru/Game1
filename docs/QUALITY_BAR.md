# 品質基準（QUALITY_BAR）

フィールド 1 枚を「完成」と判定するための基準。全 16 フィールドで同じ基準を使う。

判定の主体は依頼者。ただし依頼者が指定した締切までは、Claude Code が自己判定で
改善ループを回し続ける。締切時点での最良版を提出する。

比較対象は `refs/reference_evening.png`（依頼者の過去作、Godot 3D 製）。
**等倍・ネイティブ解像度で並置して比較すること。** 縮小表示すると差が消える。

---

## 基準 A — 見た目（主判定・目視）

7 項目すべてが「参考画像と同等以上」で合格。1 つでも明確に劣れば不合格。

### A-1 情報量

画面のどこを見ても何か描いてある。単色の平面が広く占めていない。

- 見る点: 路面、壁、屋根、地面の空き。拡大せず等倍で見て、のっぺりした領域が無いか
- 参考画像の路面は砂利アスファルトで、1 画素ごとにアルベドが散っている
- 不合格の例: 屋根が一色の斜面、壁が一色の矩形、地面が均一なノイズだけ
- 補助の目安（目標ではなく診断）: 画面を 32×32 px に区切り、局所の輝度分散が
  下位 10% の区画がどこかを図示する。そこが単色の平面

### A-2 素材感

拡大しなくても、それが何でできているか分かる。

- 見る点: 壁がコンクリートか木か モルタルか トタンか、屋根が瓦かスレートか陸屋根か
- 素材ごとに、粗さ・反射・色の散り方・目地や継ぎ目の間隔が違うこと
- 不合格の例: 全部の壁が同じノイズで色だけ違う

### A-3 立体感

建物が箱ではない。面と面の間に影が落ちている。

- 必須の凹凸: 軒の出、庇、雨樋、水切り、窓枠の落ち込み、基礎の段差、
  戸袋、換気口、室外機、看板の厚み
- 見る点: 建物の輪郭が単純な多角形になっていないか。壁面に自分の影が出ているか
- 参考画像の建物は、横線（下見板）と白いモールで面が分割されている
- 不合格の例: 窓が壁に描いた矩形、屋根が壁の上に乗った三角形だけ

### A-4 個体差（同じ建物を存在させない）

**同一のフィールド内、および町全体で、まったく同じ建物を 2 つ以上置かない。**

- 変える要素: 間口、奥行き、階数、階高、屋根の形と勾配、屋根材、壁材、色、
  窓の数と配置と大きさ、庇の有無と形、看板、シャッターの色、塀の種類、
  基礎の高さ、玄関の位置、付属物（室外機・物干し・アンテナ・雨戸）
- 同じ「種別」（例: shop_shutter）でも、上記の組み合わせが一致してはいけない
- F13 倉ノ前ニュータウンは例外。「同じ形の家が並ぶ」ことが怖さの芯なので、
  外形は揃える。ただし**経年（A-5）と付属物は個体ごとに変える**。
  「一軒だけ違う家を見つける」ためには、他が揃っている必要がある
- 検証は B-6 で自動化する

### A-5 経年（汚れ・シミ）

新築のように見えない。日本の地方都市の、手入れが行き届いていない町並み。

建物ごとに個別の値を持たせること（一律のオーバーレイにしない）。

| 種類 | 出る場所 | 見え方 |
|---|---|---|
| 雨だれ | 窓の下、庇の端、看板の下、水切りの下 | 縦の筋。上が濃く下へ薄れる |
| 苔・藻 | 基礎、塀の根本、北面、雨のかかる面 | 緑〜黒。地面から 0.3〜0.8 m |
| 錆 | シャッター、雨樋、金具、手すり、金網 | 茶。継ぎ目と下端から |
| 退色 | 南面と西面、看板、のれん、プラスチック | 彩度が落ちる。日の当たる面ほど |
| ひび | モルタル、コンクリート、基礎、舗装 | 細い線。開口部の角から斜めに |
| 補修跡 | 舗装、壁 | 周囲と色の違う矩形や帯 |
| 埃・くすみ | 窓ガラス、看板、シャッター | 全体の彩度と明度を落とす |
| 剥がれ | 塗装、ポスター、タイル | 下地の色が出る |

- 経年の度合いは建物ごとに変える。同じ通りでも、手入れされた店と
  放置された店が混在すること
- 接地部（地面と建物の境）は必ず暗く汚れていること。ここが綺麗だと浮く
- 不合格の例: 全建物に同じ汚れテクスチャが同じ強さで乗っている

### A-6 馴染み（接地）

オブジェクトが背景から浮いていない。

- 見る点: ビルボードのスプライトと 3D の建物で、粒の粗さ・彩度・
  コントラストが揃っているか
- 足元に接地の影があるか
- 不合格の例: 自販機だけ彩度が高い、街灯だけ線が細い、
  地面に置いた物が浮いて見える

### A-7 場所らしさ

そのフィールドが何の場所か、説明なしで分かる。

- 各フィールドの `docs/field/<ID>_spec.md` のランドマークから、
  **最低 3 つ**を見た目として実装していること
- 別のフィールドのスクリーンショットと並べて、取り違えないこと
- 不合格の例: 商店街と団地とニュータウンが同じ画面に見える

## 基準 B — 機能（副判定・自動検証）

失敗すればバグなので、数値で扱ってよい。全項目クリアが必須。

| ID | 項目 | 基準 |
|---|---|---|
| B-1 | 到達性 | 調べ物・出入口の全点に歩いて到達できる（塗りつぶし検証） |
| B-2 | ちらつき | 等速パン 60 フレームの隣接フレーム MAD が、単色アルベドの下限の 2 倍以内。屋根・斜面を切り出した MAD も個別に測る |
| B-3 | フレーム時間 | 16.7 ms 以内（60 fps）。フィールド全体を読み込んだ状態で |
| B-4 | 遮蔽 | 主人公が完全に隠れる状態が発生しない（フェードが効いている） |
| B-5 | 読み込み | フィールドの生成・読み込みが 3 秒以内。AO はキャッシュから |
| B-6 | 個体差 | 同一フィールド内で、建物のパラメータ組（間口・奥行き・階数・屋根形状・屋根材・壁材・色・窓配置・付属物・経年値）が完全一致する建物が **0 組**。町全体でも一致 0 組。F13 は外形の一致を許すが、経年値と付属物の一致は 0 組 |
| B-7 | 材質の漏れ | 全マテリアルを列挙し、フィルタ設定（異方性・ミップマップ）が漏れているものが 0 |

## 基準 C — 4 時間帯（副判定）

morning / noon / evening / night すべてで確認する。

| ID | 項目 | 基準 |
|---|---|---|
| C-1 | 破綻なし | 4 時間帯すべてで、白飛び・黒潰れ・色転びが無い |
| C-2 | 夜の光源 | 夜に何が光っているかが明確。光る物と光らない物の区別が意図どおり。`spec.md` の「差し色」が読める |
| C-3 | 光の較正 | ART_SPEC の規範値（ambient_energy、sun_energy、Filmic white 1.0、露出 1.15、ao_light_affect 0）を変更していない。影比は結果値なので追わない |
| C-4 | 怖さの芯 | `spec.md` の「怖さの芯」が、絵として成立する下地があるか。例: F05「シャッター街の一店だけ商品が新しい」→ 駄菓子屋だけが明るく読めること |
| C-5 | 環境音 | `spec.md` の環境音の記述と、絵の印象が矛盾しないこと（音の実装は不要。絵の側の整合だけ見る） |

## 改善ループの回し方

依頼者が指定した締切まで、以下を繰り返す。締切前に自己判定で合格しても止めない。

### 1 周の手順

1. 変更を 1 つか 2 つ加える（多く変えすぎない。何が効いたか分からなくなる）
2. 4 時間帯を撮影する。夕方は参考画像との等倍並置も作る
3. 基準 A の 7 項目を自己採点する（○ / △ / ×）。理由を 1 行ずつ書く
4. 基準 B を自動検証する
5. `docs/quality/<ID>/log.md` に 1 行追記する
   （周回番号、変更内容、A の 7 項目、B の合否、所見）
6. スクリーンショットを `docs/quality/<ID>/iter_NNN/` に保存する（消さない）

### 最良版の管理

- **前周より悪化したら、その変更を取り消す。** 悪化の判定は基準 A の
  ○ の数が減ったか、× が増えたか
- 最良版を `docs/quality/<ID>/best/` に保持し、上書きしていく
- 締切時点の提出物は「最良版」であって「最終周」ではない

### 止まる条件

以下のときは締切前でも一度報告し、指示を待つこと。

- 同じ項目を **3 周続けて改善できない**（手法の限界に当たっている）
- 基準 A を上げるために、歩行マスク・調べ物の座標・2D 地図の配置を
  変更する必要が生じた（設計資産の変更は勝手に行わない）
- 基準 B が 1 つでも落ちた状態から 2 周で戻せない

### 変更してよいもの / いけないもの

| | |
|---|---|
| 変更してよい | 建物のディテール、テクスチャ、経年、マテリアル、配置物の種類と位置、光源の追加、近景の埋め方 |
| 変更してはいけない | 歩行可能マスクの形、調べ物・出入口の座標、建物の階数と位置（2D 地図に従う）、ART_SPEC の光の規範値、カメラ設定 |

やむを得ず変更が必要と判断した場合は、変更せずに報告して指示を待つこと。

### 提出物

締切時に以下を出す。

- 最良版の 4 時間帯（等倍 PNG）
- 参考画像との等倍並置（夕方）
- 基準 A の自己採点（最終）
- 基準 B の検証結果
- `log.md` の全周分
- 全周のサムネイル一覧（改善の推移が見える形で）
- 3 周改善できなかった項目と、その理由
