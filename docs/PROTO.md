# 縦切りプロトタイプ（F-2 / G-2）— 8/1〜8/3、NPC 2 人、調査対象 1 つ

2026-09-06。設計は [DESIGN_STATE.md](DESIGN_STATE.md)。背景は lookdev シーンをそのまま使い、新規素材は無い
（人物と鳥居はスクリプトで生成した単色の板）。

## 起動と操作

```sh
godot --path . res://scenes/proto.tscn
```

| キー | 動作 |
| --- | --- |
| WASD / 矢印 | 移動（画面の上がカメラの前方） |
| E | 近くの人と話す / 神社を調べる |
| 1〜4 | 選択肢 |
| Enter / Space | 台詞を進める・閉じる |
| N | 手帳（自分が誰に何を言ったか。真実 / 嘘 / 黙った） |
| T | その日を終える（伝播と反応の処理 → 翌日。オートセーブ） |
| F1 | デバッグ画面（全状態。suspicion の内部値、信念の出所、矛盾、保留中の反応、Event 再生との照合） |
| F5 / F9 | セーブ / ロード（`user://proto_save.json`。スナップショットが正、Event 列は監査用） |
| Esc | 終了 |

登場: 佳苗（幼なじみ。7/31 の夕方に参道で主人公と美咲を見ている）、直人（美咲の兄。あの夜、鈴の音を聞いた）、
岩戸神社（調べると日ごとに何かが起きる。2 日目にリボンを見つけ、記憶の欠落が 1 つ開示される）。

スクリーンショット: `docs/proto/01_prologue.png` 〜 `07_day2_intro.png`（`-- proto_shot=<dir>` でデモ操作を自動再生して撮る）。

## 構成

| ファイル | 役割 |
| --- | --- |
| `scripts/story/story_state.gd` | エンジン。スナップショット `s`、`apply(event)`、矛盾検出、伝播、段階、問い詰め、結末、再生、不変条件 |
| `scripts/story/story_runner.gd` | 脚本を進める。会話の step（line / node / confront / end）、調査、日替わり、手帳とデバッグの整形 |
| `data/story/proto.json` | 脚本。事実（core 5 + flag 3）、NPC 2 人、3 日分の node 8 個、結末 3 種 |
| `scripts/proto.gd` + `scenes/proto.tscn` | 縦切りの UI。lookdev を子に置き、人物の板・移動・会話 UI・手帳・デバッグ・セーブ |
| `tests/story_exhaustive.gd` | 総当たりテスト（UI なし） |

状態を変える経路は `StoryState.apply()` の 10 種の Event だけ（learn / reveal / flag / say / npc_learn / confront / tick /
mark / stage_seen / ending）。UI もテストも同じ `StoryRunner` を使う。

## 総当たりテスト（G-3）

```sh
godot --headless --path . --script res://tests/story_exhaustive.gd            # 全数
godot --headless --path . --script res://tests/story_exhaustive.gd -- max_leaves=3000   # サンプル
```

1 日の行動 = 神社を調べる/調べない × 各 NPC の全 node の全選択肢（問い詰めが出れば 3 択）。深さ優先で、分岐点ごとに
スナップショットを保存して戻す。各ステップで不変条件（suspicion の範囲、stage と内部値の整合、belief が domain 内、
出所が実在する statement を参照）、葉の 1/16 で Event 列の再生とスナップショットの完全一致を検査する。

結果（2026-09-06、`data/story/proto.json`）:

| 項目 | 値 |
| --- | --- |
| 葉（3 日分の選択列） | **186,896** |
| ステップ | 861,127 |
| 所要時間 | 79 秒（ヘッドレス） |
| 結末の分布 | 隠し通した 101,248 / 共犯 52,000 / 露見 33,648 |
| 問い詰めの到達 | 告白 9,064 / 否認 9,064 / 沈黙 9,064（段階 3 に 3 日で届く） |
| node / 選択肢の到達 | 8/8、27/27 |
| 不変条件違反・再生不一致 | **0** |

最初の実行で 1 件見つかった不一致（結末と進行の帳簿をランナーが Event を通さず直接書いていた）は、
Event（mark / stage_seen / ending）に統一して解消した。「状態を直接書く経路を作らない」が実際に効いた例。

31 日規模では全数は不可能（1 日 ≈ 50 分岐で 50^31）。`max_leaves=N` の打ち切りがあるので、その時点で
乱数シード付きのランダム経路サンプリングに置き換える。

## 脚本の作業量（G-1f の所見）

3 日分を実際に書いた。

- core 事実 5 個、flag 3 個。node 8 個（1 日 1 NPC につき 1〜2 問）、各 node に選択肢 3〜4 と返答 3〜4 本。
  NPC ごとに段階の台詞 3 本、問い詰めの台詞 1 + 帰結 3 本、断絶・協力者・待機の台詞。結末 3 本。
- **JSON の行数は約 210 行、台詞は約 60 本。** 書くのに要したのは 1 時間弱。
- 実際に書いていて重かったのは「事実の定義」ではなく **返答の分岐**（嘘の値ごとに返答を変えたい場面が出る。
  `lie_<value>` で対応した）と、**段階の挙動を NPC ごとに 3 本ずつ書く**こと。
- NPC ごとの信念表（core × NPC）は脚本側で書かなかった。`observe`（その NPC が自分で知っていること）を
  NPC につき 1〜2 個書くだけで、残りはエンジンが発言と伝播から作る。**480 エントリを人が書く必要は無い。**
  脚本が書くのは「NPC が最初から知っていること」と「質問と返答」だけで、信念は派生物。
- 31 日に伸ばすと: core 10、flag 40、node 60〜90（1 日 2〜3 問）、台詞 500〜700 本。台詞の量は普通の ADV の規模で、
  状態管理が足かせになる量ではない。**耐えられる。** ただし「段階の挙動」を NPC × 段階 × 状況で書き分けると膨らむので、
  段階の台詞は NPC につき 3 本を基本にし、場面依存の言い換えは `stage_lines` の day 上書きで足す設計にする。

## 3 日で分かったこと（F-3 の暫定回答。判定は依頼者）

- **嘘が 2〜3 日後に効く経路は動いている。** 1 日目に佳苗へ「家にいた」と嘘 → 2 日目に直人へ別の嘘 → 伝播 →
  3 日目に佳苗が同じ質問を繰り返し（段階 1 の挙動）、答えを変えると自己矛盾で段階 3 → 問い詰め。
  総当たりでは 186,896 通り中 27,192 通りが問い詰めに到達する（14.5%）。
- **真実を言う選択が「一度試して二度と選ばない」ものになっていない。** 3 日目に直人へ核心を告げると協力者になり、
  結末は「共犯」（52,000 通り）。露見（33,648）より多い。ただし trust が足りない相手に告げると翌日広まる。
- 緊張が成立するかは、段階の挙動の台詞が「見える」かどうかに掛かっている。単色の板では表情が無いので、
  地の文で明示している。ここは実物のスプライトが入ってから判定し直す。
- デバッグ画面は 1 画面に収まっている（NPC 2 人・core 5）。NPC 8 人・core 10 でも NPC ごとのタブに分ければ足りる。
- セーブは JSON 1 ファイル（3 日で 20 KB 前後）。スナップショットを正にしたので、脚本を直しても既存セーブは壊れない。

## 分かっている限界

- 会話の順序（神社 → 佳苗 → 直人）が状態に影響しない脚本なので、総当たりは順序を固定している。
  順序が効く脚本（同席者・目撃）を書いたら、順序も分岐に含める。
- 人物は板。段階の挙動は地の文だけ。演出は範囲外。
- lookdev のカメラ（俯角 42 / FOV 18）で主人公を追従させると、画面に入る街路は 20 m 程度。3 日分の行動範囲としては足りる。
