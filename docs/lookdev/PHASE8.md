わかったこと:

1. **夕方の見え方は field_yaw の符号で決まる。** 規範値の太陽（方位 165、仰角 13、カメラ基準）は「奥から手前へ」の逆光で、
   3 タイル幅（3.4 m）の通りに 2 階建て（軒高 6〜6.6 m）が並ぶと、通りが太陽の向きから ±15° 以内に無い限り路面に日が入らない
   （仰角 13° だと 6.5 m の建物の影は 28 m）。合うのは −15 付近だけ。+15〜45 は画面平均 L が 23〜27 で lookdev の夕方（60 前後）の半分以下。
2. **手前の列が主人公を隠す。** 俯角 42° では、通りの中央に立つ主人公と手前の 2 階建て（壁まで 1.7〜2.9 m）の間で視線が壁に当たる。
   通りがカメラ前方から 30° 以上振れると、歩行中の 84〜96 % のフレームで手前の建物を透過することになり、
   「壁を半透明にする」方式（H-6b）は成り立たない。0 / −15 では 0 フレーム。
3. **屋根が画面の 30〜56 % を占める。** 2 階建てが両側に並ぶ通りを 42° で見ると、正面壁は最大でも 27 %。
   商店の「顔」（シャッター・暖簾・看板）は −15 では 10 % で、看板の字は読めない。
4. フィールド外（余白）は −15 / 0 で 5 % 前後、±30〜45 で 13〜24 %（西端 x = 9 の通りにいるので西の余白が入る）。
   フィールド外は今は同じ地面テクスチャの板で埋めている（`margin_*`、AO 無し）。
5. lookdev 第 6 節の「主要な通りは 15〜40° 振る」は、通りの両側が空いていた lookdev のレイアウトでの結論だった。
   狭い通り + 2 階建てには当てはまらない。

**F05 は field_yaw −15 にした。** 商店の正面をもっと見せたければ、次のどれかが要る（判断は依頼者）:
(a) 通りを 4〜5 タイルに広げる（F05.png の 3 タイルを変える）、(b) 西側の列を平屋にする、
(c) 手前の列を透過ではなく「屋根と 2 階を切り取る」方式に変える（H-6b の再設計）、(d) 夕方の見え方を「通りは暗く、屋根と奥だけ明るい」で受け入れる。

  W と D（または A）を同時に押す必要があり、通りの軸と入力の軸がずれる感じが出る。斜めの通りを採るなら、通りに沿って入力を吸着させる補正が要る。

  最初の自動歩行は一直線に歩いて車で止まり続けたので、経路探索を入れた（NPC 移動にもそのまま使える）。
