# 「3D背景 + ドット絵スプライト」方式の見え方検証

2026-09-06。Godot 4.7.2 / Forward+ / Vulkan、RTX 4060 Ti で実機レンダリングして撮影した。
参考画像（`refs/reference_evening.png`、Git 管理外）に対して、
最小の検証シーン（[scenes/lookdev.tscn](../../scenes/lookdev.tscn) +
[scripts/lookdev.gd](../../scripts/lookdev.gd)）でどこまで近づくかを確かめたもの。
**素材は作り込んでいない。** 建物は直方体、テクスチャはスクリプト生成、
スプライトは「形が分かる板」である。

比較シートはこのフォルダの `sheet_*.png`。個別ショットは
`python tools/lookdev_shots.py` で再生成できる（Git には入れない）。

## 結論

**方式としては成立する。進めてよい。** ただし、選ぶべきトレードオフが 1 つある。

- 参考画像の骨格 ── 低い太陽の長い影、暖色の光 × 寒色の影、低いキー ── は
  3D のライティングだけで出る。夕方の明度分布は参考画像とほぼ一致した。

  | 明度(L, 0-255) | 下位 5% | 中央値 | 上位 5% |
  | --- | --- | --- | --- |
  | 参考画像 | 7.8 | 40.5 | 123.5 |
  | 今回・夕方（既定設定、Glow あり） | 13.7 | 37.8 | 124.2 |
  | 今回・夕方（Glow なし） | 10.6 | 35.9 | 123.6 |

- **透視投影か正射影か**は決めなければならない。参考画像は透視投影で、
  スプライトの texel が画面ピクセルに均等に乗らないことを受け入れている。
  正射影 + 640×360 なら 1 texel = 1 px で完全に整うが、奥行き感は明らかに減る
  （`sheet_proj.png`, `sheet_sprite.png`）。**推奨は透視投影**（参考画像に近い）。
  ドット絵の整合性を最優先するなら正射影。

- 足りないものは**素材**であって方式ではない。建物のディテール（窓・看板・庇）、
  路面のクラックや継ぎ目、キャラクター、遠景。これらは仮素材の限界で、
  ライティングや後処理の設定では埋まらない。

## 実行方法

```sh
godot --path . res://scenes/lookdev.tscn
godot --path . res://scenes/lookdev.tscn -- time=evening proj=ortho tonemap=aces dof=0
```

| キー | 動作 | キー | 動作 |
| --- | --- | --- | --- |
| 1〜4 | 朝・昼・夕・夜 | O | 正射影 / 透視投影 |
| T | トーンマップ（linear→reinhard→filmic→aces→agx） | F / G / Z | DOF / Glow / Fog |
| A / I | SSAO / SSIL | P | 描画解像度 1280×720 / 640×360×2 / 426×240×3 |
| B / N | 影のやわらかさ / 影の解像度 | L | 点光源の影 |
| V / K / M | ビルボード方式 / スプライトの受光 / テクスチャフィルタ | H | HUD |
| [ ] | 太陽の高度 ±2° | , . | 太陽の方位 ±5° |
| - = | 露出 | S / Esc | 撮影（user://） / 終了 |

コマンドライン引数はキー操作と同じ項目を `key=value` で指定できる
（一覧は `scripts/lookdev.gd` 冒頭）。`shot=<絶対パス>` を付けると撮影して終了する。

## 詰めた項目ごとの所見

### カメラ（`sheet_proj.png`, `sheet_sprite.png`）

- **透視 vs 正射影**。透視は参考画像の奥行きに近い。正射影はアイソメ風に平板化するが、
  スプライトの texel が 1:1 で整う。透視ではスプライトの texel が 1 px と 2 px に
  不均一になり、拡大すると分かる（実用上は 2 倍表示で気にならない程度）。
- **FOV** は 45〜55° が参考に近い。狭いと正射影に寄り、広いと手前の建物が歪む。
- **DOF** は手前と奥に効かせた（近 9 m・遠 26 m から）。参考画像の手前左のボケは
  再現できる。ただし**DOF はドットを溶かす**。ぼける領域では Nearest の意味が無くなる。
  参考画像も同じ妥協をしているので、許容範囲の判断は依頼者に委ねる。正射影では無効。

### ライト（`sheet_sun.png`, `sheet_shadow.png`）

- 参考画像の力は**逆光の低い太陽**にある。カメラ正面〜正面左から 13° の太陽で、
  建物の影が街路を斜めに横切る。方位を正面右にすると影は手前左へ伸び、
  日の当たる壁面が画面から消える（`sun_az=165`）。どちらも成立する。
- 影は**硬い**方が参考に近い（`soft=0`）。`soft=2` は輪郭がぼけ、明度比も浅くなる。
- **影の解像度は 640×360 では 1024 で足りる**。4096 との差は見えない
  （影の縁は描画解像度でピクセル化される）。
- 点光源の影は夜に街灯の柱の影として効く。無くても絵は成立する（`sheet_night.png`）。

### WorldEnvironment（`sheet_tonemap.png`, `sheet_post.png`）

- **トーンマップは Filmic** が参考画像の分布に最も近い。ACES は黒が潰れ（下位 5% が 0.9）、
  AgX は全体が沈んで彩度が落ちる。Linear / Reinhard は中間調が暗い。
- **Fog** は極めて薄く（0.0015）。0.003 で黒が浮き、0.01 で全体が濁った。
  参考画像に霞は無い。奥だけ少し沈めたい場合のみ使う。
- **SSAO / SSIL は効果なし**。この縮尺・解像度では差が見えない（画素差分ゼロに近い）。
  コストだけかかるので **不要**。
- **Glow** は注意が要る。
  - 通常の明るさ（emission ×1〜2）では閾値 0.9 に届かず**まったく光らない**。
    発光板の emission を 4〜8 倍にすると自然な光芒、12 倍以上では塊になる。
    Glow は下位 5% の明度を 10.6 → 13.7 に持ち上げる（黒が浮く）。
  - `Sprite3D.modulate` は 8bit に丸められ **HDR にならない**。光らせたい部分は
    `StandardMaterial3D` の emission を使う板（QuadMesh）で重ねる必要がある。
  - `SHADING_MODE_UNSHADED` では **emission が無視される**（albedo のみ出力）。
    通常シェーディングで albedo を黒にして emission だけ出す。
  - `GLOW_BLEND_MODE_SOFTLIGHT` は低解像度でほぼ見えない。Additive を使った。
  - 光芒はなめらかなグラデーションで、ドットの粒とは質感が異なる。
    2 倍表示なら許容できるが、「光源だけが彩度を持つ」演出の要かどうかは要判断。

### ドット絵らしさ（`sheet_pixel.png`, `sheet_sprite.png`）

- **640×360 を整数 2 倍**が正解。1280×720 そのままだと世界のテクスチャは細かく、
  スプライトだけが 2×2 の粗いブロックに見えて浮く。426×240 では texel が 1 px 未満に
  なり、スプライトの線が欠ける。
- **Nearest は斜めの面でモアレを起こす。** 壁の横縞（8 texel 周期）が遠くの壁で
  縞ノイズになる。昼の路面では粒がリング状のモアレになる。
  `filter=mipmap`（Nearest + ミップマップ）でモアレは消えるが遠景がぼける。
  世界のテクスチャはミップマップあり、スプライトは Nearest、という使い分けが現実的。
- **Sprite3D の pixel_size は世界の texel 密度に揃える**（1/20 m）。ここが揃わないと
  スプライトの粒だけ大きさが違って見える。
- **ビルボードはカメラ正対（full）が必要。** Y 軸回転のみだと俯角ぶん縦に潰れ
  （cos 42° ≈ 0.74）、texel の行が欠ける。正対させると板の足元が地面に埋まるので、
  足元を pivot に置いて板を上半分だけ持ち上げている（`_add_billboard`）。
- スプライトの影（`alpha_cut = DISCARD`）は落ちる。街灯の柱の影が路面に出ている。

## 時間帯 4 種（`sheet_times.png`）

- **夕方**は上記のとおり参考画像に寄せた。
- **朝**は太陽を 22° に上げ、光を白寄り・環境光を明るくした。逆光構成のままなので
  壁面が青く沈む。順光にしたい場合は `sun_az` を 20〜40 にする。
- **昼**は太陽 68°。影が短く、方式の見せ場が無い。路面のモアレが最も目立つ時間帯。
- **夜**は月光（青、0.1）+ 街灯・自販機の点光源。参考画像に対応する時間帯は無い。
  発光板の Glow が絵の要になる。前作の知見「本作はホラーであり、暗さは欠点ではない」
  に従い、中央値 12 まで落としてある。

## 参考画像との差（届かなかったところ）

1. **素材の情報量。** 参考は壁の窓枠・看板・暖簾・庇、路面のクラックと補修跡がある。
   今回は縞と粒だけ。方式ではなく素材の問題。
2. **壁面の質感。** 参考は日陰の壁が「暗い藍に白い線」で読める。今回は日陰の壁が
   ほぼ黒に沈む。壁の線を明るく、環境光を少し上げるか、壁の albedo を上げる調整が要る。
   ただし環境光を上げると影が浮く。壁だけ明るくするなら albedo 側で。
3. **キャラクター。** 参考の中心は人物。今回は置いていない。
   2 世代目の検証はキャラクター 1 体を置いてから行うべき。
4. **影の明度比。** 参考画像は路面の「影の芯 / 日向の芯」= 0.120。今回の夕方（既定）で
   路面の日向（左上の帯）と建物の影の中（中央）を測ると、
   中央値どうしで **0.260**、芯どうし（日向の上位 25% / 影の下位 25%）で **0.219**。
   日向 L≈110、影 L≈29。参考画像より影がやや明るい。環境光 0.18 を 0.12〜0.14 に落とせば
   届くが、日陰の壁がさらに沈む。壁の albedo と一緒に調整する（上記 2）。
   日向の路面は RGB (136, 103, 109)、影は (36, 25, 42) で、
   「暖色の光 × 寒色の影」の構成は参考画像（日向 (115,100,111)・影 (24,30,46)）と同じ向き。

## 別リポジトリの 62 点のスプライトについて

Claude-PixelLab の `projects/iwato/assets/objects/`（62 種 × 本体・`_n`・`_s`）を見た。
自販機・街灯（LED / 水銀灯）・電柱・軽自動車・ベンチなど、**今回の街路にそのまま
必要な物が揃っている。** ただし持ち込むなら次の 3 点を決めてから。

1. **texel 密度が合わない。** 素材は 32 px タイル基準で、自販機は 64 px 中に約 50 px
   （≒ 28 px/m）。今回のシーンは 20 texel/m。そのまま置くと 1.4 倍大きく見える。
   `pixel_size` を 1/28 にすれば大きさは合うが、640×360 では 1 texel が 0.7 px になり
   線が欠ける。**シーン全体を 28 texel/m に上げる**（縦 12.9 m の狭い画角になる）か、
   素材側を 20 px/m 想定で作り直すか。
2. **視点。** 素材は「真上に近い見下ろし」のスタイルガイドで作られているが、
   実物は正面〜側面視で、ビルボードとして使える。俯角 42° のカメラには合う。
3. **ノーマルマップ（`_n`, `_s`）は Sprite3D では使えない。** Sprite3D に法線マップの
   口は無い。使うなら QuadMesh + StandardMaterial3D（albedo + normal）で板を作る。
   今回の `_add_emissive` と同じ構成でできる。

結論: **使える。ただし密度の決定が先。** 62 点を流用するなら 28 texel/m を軸に
シーン側を合わせるのが手戻りが少ない。

## 制限・注意

- スクリーンショットは `get_viewport().get_texture().get_image()` で取得しており、
  640×360 の内部解像度そのもの。シートでは Nearest で 2 倍にしている。
  実機のウィンドウ表示と同じ画素。
- 実機での撮影が前提。ヘッドレスでは撮れない。
- 参考画像は Git 管理外（`refs/`）。シートに埋め込んだ分だけリポジトリに入っている。
