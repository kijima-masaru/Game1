## T-1 テクスチャのちらつき（俯角 30°）

計測: F05 の通り（(8.5,20)、昼）で注視点を北へ 0.05 m/フレーム、60 フレーム。隣接フレームを整数シフト（±3 px）で位置合わせしてから残差の MAD を取る
（パンの流れを除き、標本化の揺れだけを見る）。屋根だけの MAD は同じパンを面積マスクで撮って屋根画素に限定した。
`field_scene.gd` の `fseq=<dir> fseq_frames=60 pan_m=0.05 wfilter=… roof_contrast=…`。GIF は `docs/lookdev/video/t1_*_x1.gif` / `_x3.gif`（Git 管理外）。

| 条件 | 屋根の MAD（平均 / 最大） | 全画面の MAD |
| --- | --- | --- |
| A Nearest + ミップマップ（現行） | 14.05 / 17.11 | 7.97 |
| Nearest + ミップ + 異方性 16x | 14.14 / 17.16 | 8.95 |
| 線形 + ミップマップ | 11.96 / 14.76 | 6.31 |
| **B 線形 + ミップ + 異方性 16x**（採用） | 12.17 / 15.00 | 7.09 |
| C B + 瓦の明暗 0.5 | 8.95 / 12.87 | 6.81 |
| （参考）B + DOF | 4.00 / 6.28 | 4.18 |
| （参考）Nearest + 異方性 + DOF | 4.33 / 6.68 | 5.42 |

**T-1a: DOF の 2 行は参考であり、採用判断の根拠にしない。** DOF はちらつきを消しているのではなく、ぼかして見えなくしているだけ
（フェーズ 4 E-0a と同じ罠）。ちらつきの測定は DOF OFF で行う（ART_SPEC 第 3 節・第 8 節に明記）。

分かったこと:

- **異方性フィルタの効果はほぼ無い**（Nearest 14.05 → 14.14、線形 11.96 → 12.17）。俯角 30° の屋根は縮小ではなく「1 texel ≒ 1 px のまま斜めに流れる」状態で、
  ミップ選択の問題ではなく、8 texel 周期の瓦の明暗そのものが 1 px 動くたびに差分を出している。
- 線形フィルタは 13 % 減らす（テクセルの縁が半 px 滲む代わり）。**瓦の明暗を半分にすると 37 % 減**。
- 設定は依頼どおり線形 + 異方性 16x を既定にした（`PixelTextures.world_filter`、`project.godot`）。異方性は地形の法面・石段（斜面）で効く見込みなので残す。
  瓦の明暗（`roof_contrast`）は既定 1.0 のまま。0.5〜0.7 にするかは素材の工程で決める。
- 材質の漏れ: 世界材質は 42 個すべて `PixelTextures.register()` を通り、フィルタを一括で切り替えられる（`FIELD ... world_mats=42 filter=5`）。
  暖かい窓（手作り材質）が Nearest のまま漏れていたので登録した。スプライト（ビルボード・主人公）は Nearest のまま。
- DOF は原因ではない。ON で MAD が下がる（−72 %）のは隠しているだけなので、評価から外した（T-1a）。
- T-1b: 分かったのはフィルタ設定ではなくテクスチャ設計の問題。「周期の明暗差を抑える」「不規則な細かさで情報量を出す」を ART_SPEC 第 3 節の素材の規則に追記した。

## T-2a 高さの形式（提案、承認待ち）

`docs/FIELD_FORMAT.md` 第 8 節。要点:

| 項目 | 値 |
| --- | --- |
| ファイル | `data/fields/<ID>_height.png`（任意。無ければ全面 0 m） |
| 解像度 | 1 px = 1 タイル（マスクと同じ）。段や坂の面はタイルの中で生成器が刻む |
| 値 | 8 bit グレー、厳密（R = G = B、A 255）。0 = 基準面、**1 階調 = 0.15 m（石段 1 段）**、255 = 38.25 m。負の高さ無し |
| 段差 | 既定は平らなタイル + 垂直の面。**0〜2 階調（0.30 m）は登れる、3 階調以上は登れない** |
| 坂 | JSON `terrain` の `slope` 矩形。中心の高さを線形補間、差に関わらず渡れる |
| 階段 | `stairs` 矩形。1 タイルに（差）段の蹴上げ 0.15 m。標準 +4 / タイル（踏面 0.29 m） |
| 橋 | `bridge` 矩形。床板と橋脚、下は埋めない。高さの二重（隧道の上の高速）は持たず、高架は `overpass` のまま |

見送った案: 半タイル解像度（階段・坂は生成で刻めるので不要）、16 bit PNG（38 m で足りる）、負の高さ（空堀・川は周りを上げる）、
2 チャンネル（R = 高さ、G = 種別。塗り絵として確認できないので、種別は JSON の矩形にした）。

資料との食い違い（報告のみ、資料は直さない）:

- F08 の石段「約 200 段 ≒ 30 m」に対し、地図の石段は x 8〜9・y 3〜16 の 14 タイル（16 m）。標準の +4 / タイルなら 56 段・8.4 m。
  200 段を地図の長さに収めると 1 タイル 14 段（踏面 8 cm）になり歩けない。**残りの段は F07 側と画面外の登りとして扱い、F08 の中は 56 段前後にする**つもり。
- F03 の「法面の階段」は南の出入口 (8,27) へ下る x 8〜9・y 23〜27 の 5 タイル。高低差は資料に無いので、標準 +4 / タイルで 20 段・3 m にする。
